# Anti-slop guardrails

Generated by workflow-init (`guardrails` module). The rules that keep agent-written code from
copying today's mess into tomorrow's. Enforced by `scripts/check.sh`; this page only explains it.

## What is enforced, and where

- **Lint and bans:** the linter config at the repo root. A banned pattern fails `scripts/check.sh`, which the
  full CI workflow runs and which you run before saying "done".
- **Debt ratchet:** violations that already existed are counted per rule in the ratchet file. A count may fall
  (record it with `scripts/check.sh --update`), never rise, and `--update` refuses to record a higher one. A new
  project starts at zero.
- **Instruction file under 100 lines:** `AGENTS.md` holds architecture, commands and core conventions. Detail
  goes to `docs/agent/RUNBOOKS.md` with a one-line pointer. A rule that can be broken without a failing command
  is a suggestion; turn it into a lint rule instead of a paragraph.

## Writing code here

1. Comments say *why*, never *what* (a business rule, a workaround). Names carry the rest. No banner comments,
   no commented-out code.
2. Separate commands (change state) from queries (return data). No hidden side effects.
3. Small units with typed inputs and outputs. A file near its length limit is split, not raised.
4. Copy the golden reference files named in `AGENTS.md`, not the nearest large file.
5. A mistake made twice becomes a custom lint rule the same day.

## Strict level only

Tighter size and complexity limits in the lint config, and:

- **Property-based tests** for pure transformations: idempotence, round trip, order independence, never crashes
  on arbitrary input. Use the stack's library (Hypothesis, fast-check, kotest-property) or a seeded generator
  driving a parameterized test.
- **A state-machine test** for each critical flow: enumerate (state, event) pairs, assert only legal transitions
  occur and no state is a dead end.
- **Review axis:** the reviewer flags any function that both mutates state and returns data.
