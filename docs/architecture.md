# Architecture

`product-studio`, `workflow-init`, `engineering-cycle`, and `product-recheck` are the four public skills, in lifecycle order. Their bodies are the orchestration contracts. Internal agent roles, core capabilities, supporting workflows, engineering references, schemas, templates, pattern libraries, and optional adapters are resources loaded progressively, and `product-recheck` reads the same set. Local YAML state is the canonical cross-session memory; Markdown artifacts are the human-reviewable outputs.

`product-studio`'s Discover phase now opens with idea validation (`references/idea-validation.md`) for a raw idea: a bounded, cited research pass and a mandatory continue-or-refine checkpoint, run before Product Lens or even intent extraction. It is a capability contract like the rest, not a fifth public skill — the public surface stays `product-studio`.

The split between the middle two is the one worth stating, because it is the one that erodes. `workflow-init` owns the **sequence** — `docs/agent/CARD.md` is hook-injected at session start, so it is what the implementing agent actually read, and it wins any disagreement. `engineering-cycle` owns the **depth** the sequence's gates point into, plus the phase after the PR merges, which no card step covers. If `engineering-cycle` ever restates the loop, there are two loops and the repository believes the wrong one.

One artifact is an exception to the resource split. The Behavior Spec is canonical at `.product-studio/artifacts/behavior-spec.md` and mirrored byte-for-byte to `docs/agent/BEHAVIORS.md`, because the implementing agent, the reviewer, and CI need it tracked in git beside the code it describes. `scripts/validate_behavior_spec.py --mirror` is the only thing keeping the two copies honest. The `<!-- behavior-spec/v1 -->` marker on line 2 is a shared contract with the `workflow-init` skill, which emits a conforming skeleton for repositories that never ran product-studio; changing the format means bumping the marker in both.

The engineering references follow the same instinct one level down. They are vendored into `skills/engineering-cycle/references/` and copied into a project's `docs/engineering/` rather than linked, so a scaffolded repository stays self-contained when the bundle is not installed. The packs this content came from did the opposite — ten of their skills pointed at a sibling `references/` directory their installer never fetched — which is why `validate_bundle.py` fails on any surviving `../../references/` link and on any route from the gate table to a file that does not exist.
